## Commands

### Backend
```bash
cd backend
source venv/bin/activate
python main.py                  # dev (port 5176)
./restart_backend.sh            # kill + restart with logging to backend.log
tail -f backend/backend.log     # watch logs
```

```bash

sudo journalctl -u stock-backend -f
```

```bash

npm run dev     # dev server (Vite, port 5173)
```


## Architecture

### Data flow
```
Odoo (JSON-RPC) → OptimizedOdooSync → last_sync_cache.json (18-20MB) → /api/products → React frontend
```

- Frontend **never** queries Odoo directly. All data comes from `/api/products`, which reads the cache file.
- Auto-sync fires 30 min **after** the previous sync finishes (`auto_sync_task()` in `main.py:1284`).
- `_is_syncing` global flag prevents overlapping syncs; `sync_watchdog_task()` resets if stuck >300 s.
- Next sync time is exposed via `X-Next-Sync` response header and tiny sidecar `backend/next_sync.json` — never by rewriting the full cache.

### Backend (`backend/main.py`)

FastAPI app on port 5176. Key responsibilities:
- Auth: token-based (`/api/login`, `/api/verify_token`). Users from `VALID_USERS` env var or `users_data.json`.
- Products: `/api/products` — serves from in-memory `_data_cache` (loaded from `last_sync_cache.json`). `?sync=true` triggers a manual sync.
- Sync status: `/api/sync/status`, `/api/sync/reset`.
- AI analysis: `/api/analyze_product`, `/api/analyze_transfers`, `/api/analyze_all_transfers` — calls OpenAI.
- Purchase orders: `/api/purchase-orders`, `/api/purchase-suggestion`.
- Movements: `/api/movements/{product_id}`.

`OdooClient` (class at `main.py:242`) handles JSON-RPC session auth and `call_kw()` calls.

### Optimized sync (`backend/optimized_sync.py`)

`OptimizedOdooSync.fetch_optimized()` runs 4 sequential phases:
1. **Discovery** — fetch warehouses, locations, product IDs.
2. **Extraction** — parallel Odoo `read_group` calls via `ThreadPoolExecutor` (high worker count for I/O-bound calls; GIL released).
3. **Processing** — build rotation, stock, revenue, PO, orderpoint maps.
4. **Cache write** — assemble and write `last_sync_cache.json` + `.gz`.

`sync_optimizer.py` provides `DynamicWorkerPool`, `CircuitBreaker`, `MetricsCollector`, `DeltaSyncManager` (supporting infrastructure).

### Frontend (`frontend/src/App.tsx`)

Single large React component file. Key patterns:
- API calls use relative paths (`/api/...`) — proxied by nginx in production, direct to `:5176` in dev (via Vite proxy or same-origin).
- Excel export uses `xlsx-js-style`.
- AI transfer analysis rendered inline per product/warehouse pair.
- Framer Motion for animations; Tailwind CSS v4 for styles.

### Odoo integration notes
- Use `read_group` for aggregation (rotation, stock, POS sales, POs) — avoid fetching raw records.
- Dotted paths (e.g. `order_id.picking_type_id.warehouse_id`) work in **domains** but NOT reliably in `read_group` groupby.
- Per-warehouse POS/PO queries submitted as separate futures — requires enough workers to run concurrently.

### Env vars (`.env` at project root)
| Var | Purpose |
|-----|---------|
| `ODOO_URL` | Odoo instance URL |
| `ODOO_DB` | Database name |
| `ODOO_USER` / `ODOO_PASS` | Odoo credentials |
| `OPENAI_API_KEY` | For AI analysis endpoints |
| `SECRET_TOKEN` | JWT-style auth token |
| `VALID_USERS` | `user:pass,user2:pass2` format |
| `USE_OPTIMIZED_SYNC` | `true` (default) or `false` for legacy path |

### Static data files
- `backend/leadtimes.json` — supplier lead times, built from root CSV files via `update_leadtimes.py`.
- `backend/last_sync_cache.json` — live Odoo snapshot, regenerated by sync. Never commit this.
- `backend/purchase_orders_cache.json` — PO cache sidecar.

### Deployment
Nginx proxies `/api` → `localhost:5176` (backend) and `/stock` → `localhost:5173` (frontend). See `nginx-stock.conf`.
